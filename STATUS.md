# STATUS — ретрофит под seo-2026-playbook

## kran-rt.ru — этап 1 (шелл/шаблон), 25.09.2026

**Контекст:** SvelteKit 2 / Svelte 5, `adapter-static`. Ключевая находка ДО патча, найденная не догадкой, а прямо в исходниках: `src/routes/+layout.ts` ставит `csr = false` для ВСЕГО сайта, и только `src/routes/+page.ts` (главная `/`) явно перекрывает это обратно в `true`. То есть клиентская гидратация Svelte в принципе существует только на ОДНОЙ странице сайта — на всех остальных (блог, park, geo, formy, obekty-opo, faq, documents, ...) это чистый HTML, переходы между страницами — обычная навигация браузера (`data-sveltekit-reload`), их JS-чанки даже физически удаляются существующим шагом postbuild как недостижимые (см. п.3 в `scripts/postbuild.mjs`, уже было в проекте).

Это меняет расчёт риска по сравнению с manipmo.ru/kranneva.ru: там пришлось выяснять эмпирически, есть ли гидратация вообще (и один раз ошиблись — на kranneva.ru grep не нашёл 'use client', но React всё равно гидратировал статический экспорт целиком). Здесь риск для 54 из 55 страниц не предположение, а факт из `+layout.ts`: гидратировать нечего. Реальный риск есть только на `/`.

**Baseline:** 55 стр., 1 FAIL (контентный, не шаблонный), 54 WARN, 0 PASS. Топ: H2 без id (54, тот же паттерн — у блога недоставало по 1 id на статью, у остальных ~30 нешаблонных страниц не было вообще), нет источников (54), сущность не названа (54), нет TOC (30), нет автора (30).

**Сделано:** новый шаг 4 добавлен в уже существующий `scripts/postbuild.mjs` (не новый файл — на этом сайте уже был postbuild-конвейер из 3 шагов, продолжила его, как и на manipmo.ru). Тот же Cyrillic-транслит slugify, что уже используется в `$lib/slug.ts` для статей блога (сохранена консистентность id между статьями блога и остальными страницами). Логика:
- `id` на все `<h2>` без id внутри `<main>` — на ВСЕХ 55 страницах, включая `/`.
- Вставка самодостаточного `<nav class="g26-toc">` (свой инлайновый `<style>`, проверка на `class="toc-d"`/`"toc-m"`/`"g26-toc"`, чтобы не задвоить блог) — на ВСЕХ страницах, КРОМЕ `build/index.html`. Главная получает только id: это единственная страница с `csr=true`, вставка нового узла там — единственное место на сайте, где теоретически мог быть риск, поэтому её патч сознательно ограничен минимальным изменением.

После патча: 56 файлов проверено, 54 изменено. «H2 без id» и «нет оглавления (TOC)» пропали из топ-10 полностью.
